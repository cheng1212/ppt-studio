# 页型卡-solution_how

- id: 页型卡-solution_how
- 卡型: 页型卡
- 标题: 原理解剖
- 来源轨: 库内装配
- 生产者: Muse
- 状态: 草案（2026-10-06）
- 版式族: 观点

## 适用场景

原理解释页：横向 3 框（输入→机制→输出）箭头连接，讲清方案如何工作；
被改变的环节（hot）用强调色＋"改变点"标注。适合讲清创新点落在哪的原理页。

## 数据字段表（字段/必填/说明）

| 字段 | 必填 | 说明 |
|---|---|---|
| id | 是 | 页 id |
| tpl | 是 | 固定 `solution_how`（闭集） |
| brow/no/kick | 是 | 页眉左/页眉右页码/金色 kick 眉题 |
| title | 是 | 标题（断言句，如"X 的关键在于改变了 Y"） |
| steps | 是 | 数组，正好 3 项：输入→机制→输出；每项：t（环节名，必填）/ d（说明，必填）/ hot（被改变环节 true/false，选填） |
| foot | 是 | 底部右注 |
| bg | 否 | 背景纹理：dots/grid/diagonal/mesh/glow（闭集） |

## 纪律

- steps 必须正好 3 项（校验闸拦截），顺序固定为输入→机制→输出。
- hot 标记的环节必须有"改变点"标注且仅有一个被改变环节为主叙事，不许满屏高亮。
- d 只许一句话说明，不许展开技术细节。
- 配色走主题令牌，不许在字段里写色值。

# 每步技能供给层建设计划（2026-10-06）

> 用户原话："确保你在做每一步的时候，能够用到、能够拿到对应的技能。
> 选主题拿主题库技能、封面页拿封面页技能、数据拿内容页数据功能、对比拿对比知识。
> 这个 Agent 应该怎么样用程序去约束它或协调它？"
> 架构（已拍板）：**选型归程序，填空归 LLM**；约束三件套＝输入约束（知识包）＋
> 输出约束（schema 白名单，现有）＋关口约束（校验闸，现有）。

## 三件交付

### 1. 程序/卡库索引.py（新建）
程序启动时扫描卡库，内存建索引（不手写注册表，改卡即改行为）：
- 扫 `库/页型/卡片/页型卡-*.md`：抽 `## 适用场景`、`## 纪律`、版式族字段（K7 要求的那
  个）、`## 数据字段表`；建 `意图→[tpl]`、`族→[tpl]`
- 扫 `库/主题/卡片/主题卡-*.md`：抽 `## 匹配标签`（深浅/行业/气质/场景/关键词）、
  `## 一句话`、`## 设计纪律`、`## css路径`；建 `标签→[theme]`
- 读 `规约/版式族.json`：族说明＋选型口诀
- 与 `规约/选型规约.json` 的"映射"做交叉校验：索引命中的意图/tpl 若不在选型规约
  映射内，打印 WARN（不自动改规约，规约是手定策源）
- 对外 API：`load_index()`、`知识包_页型(tpl)`（适用场景＋纪律＋族口诀摘要）、
  `知识包_主题(theme)`（一句话＋设计纪律＋配色语义摘要）、`意图查页型(意图)`

### 2. 知识包组装（改 程序/内容生成.py 的 生成briefs）
每页 brief 新增两个键（只给本页需要的，不给全库）：
- `"主题知识"`: {主题id, 一句话， 设计纪律（摘 3–5 条）, 配色语义（accent 角色说明）}
  ——主题 id 从大纲的主题推荐取（读 cmd_一句话/cmd_收集 的传参，把主题 id 传进
  生成briefs；若大纲无主题则该键为 None，writer 不许自选主题）
- `"版式族知识"`: {族， 何时用， 选型口诀}
- 保持 brief JSON 可序列化、体积克制（摘要不贴整卡）

### 3. 程序/意图识别.py（新建，LLM 窄接口＋关键词回退）
- `识别(一句话, llm_cmd=None)` → `{维度: 取值}`：
  - 有 `llm_cmd`（环境变量 `PPT_LLM_CMD` 或参数）：走 shell 调 LLM（stdin JSON
    `{一句话, 候选维度}`，stdout JSON `{维度: 取值}`），与 _run_writer 同模式
    （timeout/retries）；**输出必须命中闭集**，闭集从 `主题推荐.py` 的
    `意图词典/深浅意图/标签到意图` 程序化抽取（不许手抄枚举，漂移即错）；
    越界/非 JSON → 记错重试，耗尽则回退关键词
  - 无 `llm_cmd`：直接复用 `主题推荐.py.抽取意图`（确定性回退，本沙箱走这条）
- prompt 模板放文件内常量：只许输出 JSON，只许闭集取值，禁用解释文字
- `一句话.py` 接入：先调意图识别（LLM），失败/无配置回退原关键词路径；
  命令行加 `--意图 llm|关键词`（默认 llm，有回退）
- 测试：用 stub shell 命令（如 `echo '{"题材":"科技"}'` 类的固定 JSON）验证
  闭集校验逻辑；无 llm_cmd 时验证回退与现状一致

## 约束

# 提问哲学（v1）

> 大模型负责灵感，固定算法负责笼子。
> 我们不直接把用户原话丢给大模型，也不让大模型自由发挥。
> 每一次提问 = 固定格式的输入 + 固定模板的话术 + 固定规则的校验。

## 五条原则

1. **先归约，再提问**：用户输入必须先经固定规则拆解成结构化 JSON（题材/行业/受众/场景/情绪/关键词/禁忌），再喂给大模型。原话直接提问 = 天马行空的开始。
2. **话术模板固定**：提问话术是模板，只填归约 JSON，不许临场发挥改措辞。模板版本化，改模板要走规约评审。
3. **先分析，后生成**：模板第一步永远要求大模型先做领域分析（一句话说出"这个行业×场景×情绪的视觉/内容诉求是什么"），再出方案。分析过程即"会问"的体现，也是事后可检查的依据。
4. **每个方案带推理**：要求大模型为每个输出项给一句话"设计推理"（为什么贴合需求）。说不出为什么的方案 = 乱生成的方案，直接打回。
5. **输出必过闸**：大模型输出必须通过固定校验闸（格式合法/业务规则/去重/互异性）。不过闸→指出哪项→打回重生成，**不自动修正**（自动改会破坏设计意图，改完的不是它想的了）。

## 标准六段式模板

```
① 角色：你是资深<领域>专家。
② 结构化需求：用户需求（JSON）：{归约JSON}
③ 分步指令：第一步做领域分析（一句话）；第二步按以下字段生成N个方案
④ 输出字段：逐字段列出，含格式要求（如色值#RRGGBB、字数上限）
⑤ 硬约束：差异要求（N个必须拉开差距）+ 禁忌清单（从归约里填）+ 防套娃声明
⑥ 格式要求：只输出JSON数组/指定格式，不要markdown、不要解释
```

## 典范：主题生成（2026-10-06 实测）

- 归约："双11电商大促战报" → {行业:电商, 受众:管理层, 场景:复盘汇报, 情绪:[热烈,紧迫,胜利感], 禁忌:[性冷淡风,低饱和莫兰迪,文艺小清新]}
- 提问：六段式模板，大模型输出 4 套主题（霓虹午夜/开门红/薄荷爆单/曜石青），每套带设计推理
- 校验：四道闸（格式/对比度/去重/互异）实测抓出"薄荷爆单"2 处对比度问题，打回修正后 PASS
- 呈现：HTML 卡片，用户点选

## 新增 LLM 提问检查清单

- [ ] 输入是否先归约成固定 JSON？归约规则写在哪？
- [ ] 话术是否为固定模板？模板版本号？
- [ ] 是否要求先分析后生成？
- [ ] 每个方案是否带一句话推理？
- [ ] 硬约束是否写死（差异/禁忌/防套娃）？
- [ ] 输出格式是否唯一指定（不要 markdown）？
- [ ] 校验闸是哪几道？不过闸是打回还是自动修？（必须打回）
- [ ] 大模型调用失败/无 key 时有无离线兜底？兜底输出是否同一 JSON 形状？

## 与现有规约的关系

- 本文件是总纲；各场景规约是分则，分则的提示词模板必须符合本文件的六段式。
- 例外需经用户批准，并在分则中注明偏离了哪条原则。
